# 0002. Captions come from the player's own timedtext request + our refetch with its `pot`

- Status: Accepted
- Date: 2026-10-16
- Evidence: docs/plan.md §4; docs/spikes.md §1 (run 2, real Chrome)

## Context

`/api/timedtext` needs a PoToken (`pot`) generated by the player; without it the response is an empty
`200`. The spike in a real Chrome profile showed:

- the player itself requests `fmt=json3` with `pot`;
- a `pot` works for every track of **the same video**, for `fmt` changes, for `tlang=en`, with a
  track's `baseUrl`, and repeatedly; it does **not** work for another video;
- the player only requests captions when they are on; `setOption('captions','track', …)` triggers the
  request within ~50 ms but **persists** `yt-player-caption-sticky-language` and
  `yt-player-caption-persistence` in youtube.com localStorage, after which YouTube shows captions — or
  machine-translated Thai — on every video;
- SPA navigation: Thai json3 is available ~100 ms after the player reports the new video.

## Decision

MAIN-world script (`entrypoints/youtube-main.content.ts`), per video (`v` from the player response):

1. Read `captionTracks` from `getPlayerResponse()`. No `languageCode === 'th'` → status
   "No Thai subtitles"; stop. Never treat `tlang=th` responses as Thai captions.
2. Observe timedtext requests (XHR + fetch patch at `document_start`), filtered by `v`, deduped.
   Take `pot` (+ `c`, `cver`) from the first one for the current video.
3. If none arrives within ~1.5 s after the player response is ready: snapshot the two caption
   localStorage keys and the current track, hide `.ytp-caption-window-container`, call
   `loadModule('captions')` + `setOption('captions','track', thai)`, take the `pot`, then **restore**
   the previous track (off) and both keys byte-for-byte (remove them if they were absent).
4. With that `pot`, immediately fetch both tracks ourselves, so `pot` lifetime doesn't matter
   (`credentials: 'include'`, native `fetch` saved before patching):
   - Thai: manual track if present, else `asr` — from the track's `baseUrl` + `pot` + `fmt=json3`;
   - English: `en` manual track if present, else the Thai URL + `tlang=en`.
5. Post results to the isolated content script (`window.postMessage`, checked `source`); the content
   script sends cues to the SW, which caches them in IndexedDB by `[videoId+vssId]`.
6. Fallback behind the same `CaptionSource` interface: transcript panel (InnerTube `get_transcript`).

## Consequences

- Turning captions on/off by the user must keep working: our native-caption CSS is only active while
  the overlay is shown, and we never leave the sticky keys changed.
- Users who keep YouTube captions on get Thai with no `setOption` at all.
- E2E tests stub `/api/timedtext` with recorded json3; live captions cannot be tested under automation.
- Open, non-blocking: `pot` lifetime > 7 min, logged-out profiles, pre-roll ads. Re-check on the
  manual release checklist.
